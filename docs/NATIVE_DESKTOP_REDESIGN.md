# QuickPLS Native Desktop Workbench

QuickPLS uses a compact Windows-first scientific workbench. Its layout density and workflow are familiar to users of desktop PLS-SEM software while its code, terminology, validation, branding, project format, and numerical engine remain independently implemented.

## Production Shell

The production entry point renders `NativeDesktopApp` directly. The active shell has four document surfaces:

- Launcher/Project: New, Open, sample, and recent-project access before a project is loaded; afterward, a compact Workspace Explorer for Data, named Models, and saved report aliases.
- Data: dataset tree, paged spreadsheet view, variable view, data quality, import details, and selected-variable properties.
- Model: indicator and construct navigator, live React Flow model canvas, selected-object properties, and the context command toolbar.
- Results: completed-run selector, capability-derived result tree, graphical estimates, and available result tables.

PLS Algorithm, Consistent PLS, Weighted PLS, bounded GSCA ALS, CCA composite residual diagnostics, Importance-Performance Map Analysis, bounded CB-SEM / CFA, Bootstrapping, Structural Path Randomization, MICOM and Two-Group Permutation MGA, PLSpredict / CVPAT, Necessary Condition Analysis, Principal Component Analysis, and Regression open in one searchable modal calculation dialog. Model-bound workflows use the generic `Calculate` command; model-free NCA, PCA, OLS, and binary logistic regression use the same dialog through Data's `Analyze…` command. A categorized listbox scales the method catalog without a ribbon, tabs, or per-method menu entries. Export, method scope, run details and logs, preferences, shortcuts, and About are on-demand dialogs. Setup, Run, Report, Trust, and Settings are not permanent global workspaces.

The HTML shell does not draw a title bar. Tauri supplies the single Windows title bar, starts maximized with a DPI-safe 1280 x 720 restored size, and enforces a 1024 x 700 minimum window.

## Primary Workflow

1. Start at the quiet Launcher and create a project, open a saved project, reopen a recent project, or load the sample project. Once a project is open, use the Workspace Explorer to open Data, create, rename, switch, or delete named editable models, and open saved report aliases. Model switching restores that model's own positions and routing without treating navigation alone as a scientific edit.
2. Import raw data, covariance matrices, or correlation matrices through the native setup dialog. Matrix imports require their study sample size; missing markers are applied during import. Then use Data view, Variable view, Data Quality, and Import Details without leaving the data workbench. The native grid requests bounded pages from the active dataset; the UI offers 50, 100, and 250 cases per page and reports loading and retrieval failures in the table region. The navigator joins backend-owned dataset snapshots to backend-owned import, metadata, and recode lineage, lets the user activate a retained version, and searches variables by name or label. Selected-variable properties edit the label, measurement scale, and theoretical range while keeping physical type and applied missing markers factual and read-only. For a raw writable native dataset, Recode maps typed values into a new derived column across the complete Arrow dataset, applies an explicit keep-original, set-missing, or error policy to unmapped values, and creates an immutable fingerprinted descendant. Browser preview and read-only projects do not perform this mutation.
3. When an imported dataset has no editable model yet, Data shows `New Model…` as the primary next action (`Ctrl+Shift+N`). Creating it activates the model and opens Model automatically. Drag variables to the live canvas, create and rename constructs, connect or edit paths, arrange the diagram, undo or redo changes, pan and zoom, and delete the current selection. The optional properties pane edits the selected construct or path. For the promoted moderation scope, select an existing substantive path and choose `Moderating Effect...`; the dialog selects a measured moderator and atomically creates the protected two-stage product construct, product path, and missing moderator main-effect path. For the bounded native HOC scope, create at least two measured reflective constructs with no structural paths, choose `Higher-Order Construct...`, select the lower-order components, and then add exactly one HOC-to-measured-outcome path. The editable HOC remains indicator-free because stage 2 uses generated lower-order component scores.
4. Use `Calculate` (or Data's model-free `Analyze…`) and select one of the fourteen workflows. Structural Path Randomization is the single-model Freedman-Lane structural-path routine and is deliberately separate from group comparison. MICOM and Two-Group Permutation MGA profiles the complete native dataset, requires an unassigned grouping variable plus explicit ordered A/B values and at least ten complete model cases per group, fixes path weighting, standardized data, and listwise deletion, and requires 5,000–10,000 usable permutations plus explicit MICOM Step 1 confirmation. It reports group paths/R²/loadings/weights, A-minus-B comparisons, two-tailed permutation evidence, and MICOM Steps 1–3. The dialog keeps an isolated settings draft, validates the applicable dataset and model before dispatch, keeps method-specific settings mutually exclusive, locks settings while active, and displays only progress and log entries reported by the native job. Consistent PLS accepts reflective path/factor-weighted models with at least two indicators per construct and rejects inadmissible corrected correlations. Weighted PLS requires a positive finite numeric case-weight variable and standardized preprocessing; the native engine validates the complete column. CCA is limited to standardized, listwise, reflective recursive composite path models with path/factor weighting, at least two constructs, at least one structural path, and no controls, interactions, higher-order constructs, case weights, or resampling. It reports descriptive observed-versus-reproduced composite-correlation residuals only and produces no threshold, pass/fail classification, or inference; it is not full SmartPLS CCA. Importance-Performance Map Analysis selects one endogenous target and reports only its direct and indirect structural predecessors, using total PLS effects for importance and observed-range 0-100 performance from listwise-standardized scores. It does not claim theoretical-range correction, alternate SmartPLS representations, NCA integration, resampling inference, or cIPMA. CB-SEM / CFA fits single-group reflective raw-data measurement-only CFA or recursive SEM by maximum likelihood with first-loading marker identification. It reports standardized and unstandardized parameters, fit indices, residual matrices, and residual-based modification screening; mean structures, robust/ordinal/FIML estimators, bootstrap, multigroup/invariance, controls, interactions, and higher-order constructs remain unsupported. PLSpredict / CVPAT v2 retains complete numeric cases, predicts reflective endogenous indicators with train-only transforms and model fitting, and uses a fixed seeded balanced 10-fold plan repeated 10 times. It reports PLS-SEM, indicator-average, and linear-model errors, Q²_predict, and one-sided 95% aggregate benchmark tests; construct scores and the modulo-4 holdout are supplementary. Its fixed assignments are independently implemented rather than SmartPLS-randomized, and it does not compare separately saved models. Necessary Condition Analysis is a model-free observed-variable workflow with CE-FDH/CR-FDH ceilings, seeded permutation evidence, and observed-range bottlenecks; it does not claim latent-score, multiple-condition, theoretical-range, or cIPMA support. Principal Component Analysis is a model-free 2-to-50-variable correlation-matrix workflow with fixed, Kaiser, or cumulative-variance retention; it exports full complete-case scores but excludes rotation and inference. Regression is model-free: OLS uses raw numeric outcomes, ordered predictors/controls, listwise deletion, HC3 standard errors, and fixed two-sided 95% intervals; binary logistic regression requires exact complete-case 0/1 coding and uses deterministic single-worker Newton IRLS with Wald and likelihood output. Regression Bootstrapping adds bounded deterministic percentile and conditional-BCa coefficient inference for those two variants. Graph-defined PROCESS v2 authors bounded multiple-equation mediation, moderation, moderated mediation, conditional effects, simple slopes, Johnson-Neyman regions, and optional dedicated case bootstrap without copied numbered templates. These regression variants exclude automatic categorical encoding, weights, clustered errors, and broader regression families.
5. On success, Results opens automatically. Select a completed run, expand its capability-derived result tree, and inspect only the diagram or tables actually present in that run. When the fitted structural model contains a genuine indirect route, Results adds a Mediation group with direct effects, path-specific indirect products, total indirect effects, total effects, and matched Bootstrap effect inference. When the immutable completed model contains the promoted two-stage interaction, Results adds Moderation effects, conditional effects at -1/0/+1, an accessible conditional-effect plot, and only the matched available inference tables. A valid disjoint two-stage HOC adds a Higher-order construct group with component relationships, the HOC structural path, and calculation scope. Generated product and HOC pseudo-indicators do not appear as ordinary measurement evidence. A simple direct-only model receives none of these empty groups.
6. Choose `Edit Model` to return to the same live model, with the completed run still available for overlays, or choose `Export` to open the focused export dialog for CSV, XLSX, HTML, reviewer pack, or the Windows Print/PDF workflow. SVG is offered only when the completed run has a graphical model result; group-only MGA results intentionally omit it.

Method scope, provenance, run logs, and preferences remain available from menus and dialogs without competing with modeling space. Only an actionable validation or execution blocker appears in the primary path.

## State Truthfulness

- Calculation state is one of idle, queued, validating, running, cancelling, completed, failed, cancelled, or blocked.
- Progress rows and logs come only from active native jobs.
- Only completed result-backed runs appear in Results.
- The result tree is derived from outputs present in the selected run; unavailable sections and empty `N/A` tables are omitted.
- A completed run stores an immutable model snapshot and its actual calculation log. Results and exports prefer that snapshot so later model edits do not rewrite historical output; older archives without a snapshot retain their compatible live-model fallback.
- Native project reopen is split deliberately between scientific records and presentation state. The Tauri snapshot exposes the archive's canonical model catalog, immutable recipes, and validated result envelopes; the frontend reconstructs model and run content from those records and uses `layouts.workspace` only for positions, routing, pane state, and explicitly supported legacy fallback. A stale workspace run cannot replace a validated canonical result.
- Explicit save and recovery autosave send the active model as a typed `ModelSpec`. The backend upserts that model into the canonical catalog on a cloned project, writes the candidate archive, and only then replaces the in-memory project, so an invalid workspace or failed write cannot partially mutate the open scientific document. Recipe-embedded model snapshots remain immutable historical inputs.
- Workspace Explorer mutations are atomic and remain dirty until an explicit save or successful recovery autosave. Per-model presentations are stored separately from canonical scientific models. Deleting an editable model preserves immutable recipes, validated results, and saved report aliases; removing a report alias never deletes its canonical result. Results can return to their actual source model only while that editable model still exists.
- A successful calculation opens Results automatically. Edit Model returns to the live canvas without replacing it with a mock.
- Project changes are tracked semantically. The active dataset ID, immutable dataset catalog, lineage records, model, settings, and completed runs participate in the project signature, so version creation and writable-project version activation update dirty state while transient selection and hover do not. Saved writable native projects receive a debounced recovery autosave, and unsaved close uses Save / Don't Save / Cancel.
- Import, variable metadata, and Recode create backend-owned lineage records. Variable metadata edits and Recode operations create new fingerprinted dataset versions and retain their source datasets, so completed runs can still resolve their original analysis input. Exact metadata no-op edits do not create duplicate versions, and data mutations reject read-only projects.
- Dataset version navigation never invents provenance for older archives: a snapshot without a lineage record remains explicitly unknown, including its operation and timestamp. Activating a retained version changes the active dataset without rewriting either version.
- Starting another project, opening a project, selecting a recent project, or loading the sample protects unsaved work and refuses to replace the workspace while a calculation is active.

## Command Architecture

`src/native/nativeCommands.ts` is the typed registry for menu, toolbar, keyboard, and context commands. Command visibility and enablement depend on the active surface, selection, completed results, calculation state, and undo history. A visible command must dispatch a real action or be absent. The toolbar and menu share one generic Calculate entry; a typed calculation request carries the selected catalog method and an immutable settings snapshot to the controller. Pointer right-click and Shift+F10 use the same semantic native menu; the canvas does not maintain a second command surface.

Construct and path text editing uses the optional Properties pane. Enter or the selection context command opens the pane and focuses the relevant editor, avoiding browser-native prompt windows and preserving the selected object.

## Native Interaction And Accessibility

- The menu bar exposes Windows-style keyboard traversal: Left and Right move between top-level menus; Up, Down, Home, and End move within a menu; Enter or Space activates; Escape closes and restores focus.
- Data, Model, and Results expose registry-derived context commands by pointer, the Context Menu key, or Shift+F10. Keyboard-opened menus remain within the viewport and restore focus when closed.
- Global shortcuts include Ctrl+N, Ctrl+O, Ctrl+S, Ctrl+Shift+S, Ctrl+R, and Ctrl+Shift+B. Model shortcuts include V for Select, P for Path, F for Fit, Enter for selected-object properties, and Delete for the selection; shortcuts that could mutate the canvas do not fire while typing in an editable control.
- Result navigation uses tree, treeitem, and group semantics with arrow-key expansion and traversal. Data regions expose row and column counts, loading state, range descriptions, keyboard-selectable variables, and screen-reader labels.
- Focus remains visible, reduced-motion preferences disable canvas transition animation, and the compact layout collapses optional properties automatically before reducing the central work area. Users can reopen the pane as a temporary overlay when needed.

## Performance Boundaries

- Results is loaded as a separate production chunk.
- Export, method scope, and preferences are loaded only when opened.
- The obsolete ribbon/card frontend and legacy stylesheet are not imported by the production entry.
- No production JavaScript chunk may exceed Vite's 500 kB warning threshold.
- Native datasets are requested page by page instead of rendering all cases at once.
- Recode runs against the complete backend dataset and never derives a mutation from the bounded grid preview.
- Optional panes collapse before the central canvas or tables are compressed at the supported minimum size.
- React Flow's on-canvas attribution remains visible unless the project confirms React Flow Pro or written removal permission. Its exact MIT notice is retained in `THIRD_PARTY_NOTICES.md` and bundled with the installed application.

## Manual Packaged-App Acceptance

Build and launch the packaged Tauri application for native-only evidence. Verify:

- The window has exactly one Windows title bar and native window controls.
- Launcher, Data, Model, Calculation, Results, and Export are usable at 1024 x 700, 1280 x 720, and 1440 x 900 without horizontal workspace overflow or inaccessible controls.
- Project open, import, and save dialogs, unsaved-close confirmation, keyboard shortcuts, menu traversal, context menus, focus return, and window controls behave as desktop interactions.
- A genuine PLS Algorithm job reports native progress, opens completed Results automatically, exports available outputs, and returns to the same editable model.
- A genuine Bootstrapping job can be observed while active and cancelled; no idle or browser-only fixture is accepted as running-job evidence.
- The Structural Path Randomization product contract produces only its available candidate single-model Freedman-Lane inference output, which appears under the Results inference tree and participates in the existing result exports. It conditions on fixed original PLS scores, assumes exchangeable reduced-model residuals, and is not presented as group permutation, MGA, or MICOM.
- A genuine MICOM and Two-Group Permutation MGA job profiles all native rows, compares explicit ordered A/B values with at least ten complete model cases each, uses exactly 5,000–10,000 usable deterministic permutations, and reports group paths/R²/loadings/weights, their A-minus-B differences, two-tailed inference, and the MICOM v2 hierarchy under a Groups-first result tree. It omits pooled diagrams and approximate-normal inference, exports the same 16 tables plus provenance, and survives save/reopen. Failed compositional invariance blocks an invariance-supported MGA interpretation for that composite; failed Step 3 blocks full-invariance or pooling claims.
- A genuine Consistent PLS job records its current estimator and rho_A method versions, uses corrected loadings in tables and diagram overlays, exposes correction reliability and construct correlations, and fails truthfully when the corrected correlation matrix is inadmissible.
- A genuine Weighted PLS job validates its case-weight column across the complete native dataset, records the column in immutable provenance, and exposes weighted estimates plus case-weight diagnostics.
- A genuine CCA job uses a visibly constructed deterministic non-saturated `X -> Z -> Y` reflective model, records `cca_composite_residual_v1` and `recursive_standardized_composite_path_model_v1`, opens `Residual summary` automatically under Assessment, exposes exactly three finite pair rows in `Composite residuals`, exports both residual tables, and restores the same completed run after explicit save and reopen. The UI must not add thresholds, fit classifications, p values, confidence intervals, or bootstrap claims. Browser-only completed CCA fixtures are not accepted.
- A genuine `X -> M -> Y` model exposes nonempty direct, specific indirect, total indirect, and total-effect tables after PLS. A genuine Bootstrap job adds only the effect-inference rows emitted by the native resampler; it does not invent specific-path intervals. Both completed runs and their Mediation result tree survive save/reopen.
- A selected `X -> Y` path can receive one measured moderator `M`; authoring atomically produces and protects `X -> Y`, `M -> Y`, and the generated product-to-`Y` path. A genuine PLS run exposes the exact interaction coefficient, conditional effects, and conditional-effect plot; Bootstrap, BCa, studentized, and Structural Path Randomization evidence is classified once under Moderation. The run and result group survive save/reopen and reject altered product identities, settings, slopes, or inference originals.
- A native Recode transforms values beyond the first visible page, records its parent/operation/source/target lineage, preserves the source fingerprinted version, activates the descendant, marks the project dirty, and survives save/reopen. Reactivating the source must not rewrite either snapshot; browser preview and read-only projects must remain non-mutating.
- A genuine PLSpredict / CVPAT v2 job uses the documented complete-case fixed seeded 10-fold by 10-repeat plan, opens with indicator prediction, retains IA and LM columns with explicit unavailable reasons, exposes two aggregate single-model CVPAT benchmark rows, and never renders `N/A`. Its assignment digest, seed, versions, and fixed 95% one-sided alternative must survive export and reopen. Legacy v1 construct-score results remain explicitly labeled legacy.
- Completed Consistent PLS, Weighted PLS, and PLSpredict / CVPAT runs survive recovery autosave, explicit save, process reload, and reopening through Recent Projects. A completed result must pass the same archive contract before it enters the open project, so an invalid payload cannot appear successful and fail only during a later save.
- Empty Results omits fabricated tables and interpretation, while a failed or cancelled job remains distinct from a completed result-backed run.
- A 20-construct/80-indicator model remains responsive during selection, dragging, path editing, pan, zoom, and surface changes.
- Keyboard navigation, accessible names, visible focus, contrast, reduced motion, and Windows 200% scaling remain usable.

The automated packaged driver requires `QUICKPLS_CCA_NATIVE_EXPORT_PATH` to be a new absolute `.xlsx` path inside `validation/results`. It fails instead of substituting an enabled-button assertion, then opens the real Windows Save dialog, verifies the saved workbook contains `Residual summary` and `Composite residuals`, and records the file evidence in `v247_tauri_native_acceptance.json`.

## Product Boundary

QuickPLS is a proprietary, fully offline, Windows-first SmartPLS alternative. Familiar layout density and workflow do not imply copied branding, assets, proprietary wording, project-format compatibility, reverse-engineered behavior, or guaranteed numerical identity with undocumented SmartPLS behavior. Project archives, numerical engines, deterministic fingerprints, provenance rules, and Tauri command contracts remain QuickPLS-owned and independently implemented.
